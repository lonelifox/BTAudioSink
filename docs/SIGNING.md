# 代码签名：为什么不做

用户首次运行 `BTAudioSink-Setup-*.exe` 会看到 SmartScreen 的「Windows 已保护你的电脑」，
点「更多信息」→「仍要运行」即可。

**本项目不做代码签名。** 这份记录留着，是为了以后（包括自己）再想起这件事时，
不用把下面的调研重做一遍，也不容易被销售话术带偏。

## 排除掉的路

| 方案 | 成本 | 排除原因 |
|---|---|---|
| [SignPath Foundation](https://www.signpath.org/) | 免费 | 证书主体会变成 SignPath Foundation 而不是作者本人，且**每个 Release 需要人工在网页上批准一次**，与自动发布流程冲突 |
| Certum 个人版 OV | 约 ¥500–800/年 | 能消除「未知发布者」，但**仍然免不掉首次提示**，性价比不足 |
| EV 证书 | 约 ¥1150–1600/年 | 2024 年微软取消了 EV 的首个下载免检特权，现在与 OV 一样需要积累声誉。EV 唯一独有的能力是签内核驱动 `.sys`，本项目用不到 |
| Azure Artifact Signing | $9.99/月 | 微软官方最推荐，但**个人开发者仅限美国、加拿大**，中国大陆过不了身份验证 |
| 自签名证书 | 免费 | 用户机器上没有对应根证书，会被拦得比不签名更严格 |

核心事实：**2024 年起，没有任何证书能让新软件「首个下载免掉 SmartScreen 提示」**。
所有方案都只是把「未知发布者」换成具体名字，然后慢慢积累声誉。
所以花钱能买到的是标识，不是免检——这才是本项目放弃签名的原因。

## 不签名时怎么弥补

- Release 附 `SHA256SUMS.txt`（`sha256sum --tag` 格式），用户可自行核对文件完整性
- README 写明了绕过提示的具体步骤
- 源码公开可编译、CI 日志可查，把信任建立在可验证性上，而不是证书

## 如果以后改主意

1. 签名必须发生在**打包之前**：先签 `publish-installer/` 里的 exe / dll，
   再让 Inno Setup 打包；zip 同理，签完再压缩。顺序反了等于没签。
2. 自包含发布会带进来几百个 .NET 运行时 dll，它们本来就有微软签名。
   **重签会把这些文件的来源证明覆盖掉**，只需签 `BTAudioSink.exe` 和 `BTAudioSink.dll`。
3. 证书必须配 RFC 3161 时间戳。2026 年起证书有效期上限 459 天，
   没有时间戳的话证书一过期，已签名的旧包会全部失效。

> 价格与政策摘自 2026 年 11 月的微软官方文档和 CA 中文站。若隔了半年以上再重启这个话题，需要重新核对。
